# Jev呼びかけ判定（通常TTS）

設定のJevを有効化してAPIキーを保存し、「ハンズフリーの呼びかけ判定」を標準・厳しめ・リビング向けから選びます。初期値はOFFです。ON時にキー未設定・通信失敗なら会話へ送信しません。

PCでは音声設定の開始方法をハンズフリーにして、デスクトップのキャラ横マイクで待受を開始／停止します。認識後の自動送信もONにしてください。アプリ起動だけでマイクを開始する変更ではありません。

ATOM Echo／RLCDではデバイス設定のhands-free時に適用します。push-to-talk設定の手動入力は対象外です。入力モードは録音開始時に固定します。Liveは対象外です。

音声検出→文字起こし→Jev判定→既存の自動送信の順です。VADの発話・無音検出は変更しません。Jevへの1回の問い合わせで「意味のある会話か」「宛先は誰か」を別々に判定します。標準・厳しめとも、咳払い等に由来し得る単独の「フッ」「アッ」や、会話として不明瞭な断片は除外します。文字数による一律除外はせず、「はい」など意味のある短い返答は残します。

意味のある発話について、標準は明確に他人宛て・独り言のものを除外し、宛先が曖昧な文も送信します。厳しめは確実な呼びかけ・直前の回答への返事・単独の挨拶を通します。「こんにちは」は名前なしで会話開始できますが、「田中さん、こんにちは」や引用は挨拶として許可しません。通信失敗・不正応答はどちらも保留します。PCには判定中・除外・失敗を表示します。

Jevは文字起こし結果のみを見るため、実際の音が咳かどうかは分かりません。咳が完全な文章に誤認識された場合や、テレビの挨拶などは除外できないことがあります。

## リビング向け

VADと文字起こしは従来どおり。その後、Jevで会話の内容と宛先を判定します。名前・ウェイクワード・固定の言い回しは不要です。「今日のニュースを教えて」「このエラーを説明して」「旅行の計画を一緒に考えて」など、情報を調べる・説明する・相談する自然な話しかけを受け付けます。単独の挨拶も、他人宛てや引用の証拠がなければ開始候補です。

「ご飯できた？」「お皿取って」「テレビ消して」「明日は何時に出る？」「あれどこに置いた？」など生活上のやり取りは、明確にAI宛てと分からない限り unrelated / uncertain に寄せるプロンプトです。単に疑問文・命令文だから通すことはしません。開始判定には宛先の確率スコア0.92以上が必要で、標準と違って uncertain を通しません。短い継続窓内の意味的な返事だけは0.8以上で許可します。これらのスコアは実世界の精度保証ではありません。通信失敗・咳なども送信しません。これはモデルによる内容判定であり、上記例の固定文字列ブロックではありません。

受け付けたハンズフリー発話の回答が確定した後15秒間は、同じ入力元・同じキャラについて、その回答に意味的につながる短い返事も許可します。窓は回答確定を基準にし、再生完了ではありません。長文の再生後に窓が切れていたら、「そのニュースについてもう少し教えて」のように話題を含めて質問してください。除外した発話で窓を延長しません。PCでの手動会話はRLCDの窓を開きません。回答待ちが3分以上かかった場合、キャラ／Jev設定を変更した場合は窓を失効させます。

これは話者認証ではありません。テレビがAIへの質問に似た文を話す、家族が直前の質問に合う返事をする等は誤応答し得ます。同じ認識文が家族宛てにもキャラ宛てにもなり得る場合、テキストだけで完全には区別できません。会議中など確実に止めたいときはミュートしてください。通常TTSのPC・ATOM Echo・RLCD共通で、Liveや手動push-to-talkには適用しません。

Jevには認識文と、最大30秒前（厳しめ15秒）の直近回答の冒頭600文字を送ります。判定ログには本文・キーを出しません。除外した文は表情判定や音楽操作にも渡しません。

これは話者認証ではありません。会議・テレビ・独り言を確実に識別できる保証はなく、会議中は明示的にミュートしてください。認識中のデバイス表示は既存挙動を維持します。
