# Jev（任意の高速判定）

Jevは会話モデル・音声認識・TTSを置き換えません。PCアプリからTypesafeの
`jev-latest`へ短いテキストと選択肢を送り、音楽操作とキャラの表情・反応だけを判定します。
既定はOFFです。ESP32へAPIキーやJevランタイムを配置する必要はありません。

## 設定

アプリ設定のJev欄で有効化し、APIキーを保存して「接続テスト」を押します。
メディア操作と表情選択は個別にOFFにできます。
キーはElectron safeStorageで暗号化し、暗号化が利用できない環境（Linux basic_textを含む）では
起動中のメモリにのみ保持します。公開状態・ログ・キャラ書き出しにはキーを含めません。
リポジトリのテストキーを自動で読み込む機能はありません。

有効時は確定した入力文（音楽判定、最大2,000文字）と発話セグメント等（表情、最大1,200文字）が
Typesafeへ送られます。音声、生の画像、全会話履歴、再生アプリの情報は送りません。
API利用料金・データ取扱いはTypesafeの契約条件に従います。

## 音楽操作

- 対象: 次の曲、前の曲、一時停止、再開。Windowsの既存メディアセッション制御を使用。
- 通常会話: 明示的な操作と判定できれば、会話モデルを経由せず操作結果を返します。
- Live: 音声認識の**確定文**から開始。途中の文字列からは実行しません。
- 同一発話のJev経路と後続ツール呼び出しは同じ実行結果を共有し、二重スキップを防ぎます。
- 引用・否定・複数操作・曲名検索などは高速経路の対象外。判定失敗時は従来経路へ戻ります。
- 選択肢の確率と明示的指示のスコアを両方確認します。APIの`confidence`と選択確率は別の値です。
- 複数プレイヤーで対象が曖昧なら実行しません。結果不明の操作を自動再試行しません。

Jevの待ち時間上限は通常1.5秒、接続テスト5秒。音声認識の確定待ちとWindowsの操作時間は別途必要です。
Liveの音声回答速度自体を変更するものではありません。macOSでは既存のWindows専用メディア操作経路を使いません。

## 表情・仕草

許可した表情・リアクション名だけを受け取り、既存のキャラ描画／モーションへ渡します。
任意コード・任意画像パス・任意モーション命令は受け付けません。
Liveの即時判定は同時1本、待機中は最新文だけを保持し、同じセグメントの再送は抑制します。
TTSの先行判定は別の直列キュー（実行中込み最大3件）を使い、将来の文の準備で現在の表情を変更しません。
失敗時は既存のローカル表情を維持し、TTSを停止しません。
キャラ変更・新しい文・停止後に届いた古い判定は破棄します。
口は音声レベル、瞬きは既存コントローラーが引き続き所有します。

### 発話との同期

- PCのTTSは音声合成と並行してセグメントの表情を準備し、実際の再生開始時に適用します。
  合成完了より判定が遅い場合は判定完了まで待ちます（API単体の上限1.5秒、キュー最大3件）。
  準備結果は一度だけ使用でき、最大8件・60秒で失効。停止／キャラ変更後の結果は使いません。
  不確かな判定は現在の顔を維持し、失敗・無効時は従来のローカル判定で再生を継続します。
- Liveは新たに届いた意味のある句を再判定します。通常は650ms以上間隔を空け、
  最終受信分を含め1回答最大5回。完了イベントによる従来のキーワード判定の上書きを防ぎます。
  音声を待たせるバッファは追加していないため、文字が音声より遅れる場合の完全同期は保証しません。
- 通常Chatの定型待ち発話は既定で送信しません。処理中表示は継続します。

開発ログの`at`はイベントの時刻（epoch ms）です。録画と照合できますが、
`expression-applied`は描画指示の送信であり、液晶／画面への表示時刻そのものではありません。
表情の保持時間は4.5秒。表情の選択確率が75%未満、または判定が不正な場合は
`uncertain`として適用を見送り、現在の表情を上書きも延長もしません。
75%以上で明示的に選ばれたneutralは通常顔へ戻します。音楽操作のしきい値は変更しません。

デスクトップの標準5キャラは`happy / thinking / surprised`の目・眉差分を使用します。
各表情を既存の口`closed / half / open`に重ね、髪や輪郭を変更しません。
RLCDの既存モノクロ4枚をカラー差分で上書きする処理はありません。

## 新規キャラ生成

`.agents/skills/build-purupuru-avatar`に生成・合成・品質検査を統合しています。
通常6枚と髪・RLCDセットに加え、3表情の画像生成マスターから9枚の口対応差分を組み立てます。
`compose-emotions.cjs`と`validate-output.cjs --require-emotions`を使用。
新規生成は表情を必須検査し、旧キャラ／インポートは差分がなくても互換動作します。

画像生成プロンプトの基本形:

> 元画像の人物・衣装・位置・輪郭・髪を保持し、目と眉だけを指定の表情へ編集。
> 口は変更しない。目は開けたまま。背景は透過。新しい文字は追加しない。

喜び=穏やかな笑い目、考え中=視線と片眉の変化、驚き=開いた目と上げた眉。
生成画像はそのまま差し替えず、元キャンバスへ合わせて目・眉の領域だけを合成し、髪込みで目視確認します。
今回のマスターは組み込みimagegenで生成しています。

## 検証

dev起動（`app.isPackaged === false`）ではmain processのconsoleに`[Jev]`ログを出します。
操作判定・表情判定の開始／結果／所要時間、表情の適用／見送り理由、失敗の分類を確認できます。
`expression-applied`は描画側へ適用指示を送った意味で、画面描画完了の保証ではありません。
キー、本文、キャラID、生のエラーは出しません。配布版ではこのconsoleログは無効です。

`node --test desktop/tests/jev-*.test.cjs desktop/tests/emotion-sprites.test.cjs`

テストは実APIキー不要。実API確認は任意で、キーをログに出さず合成したテスト文だけを使ってください。
実際の曲送り／音声対話の体感速度はWindowsの再生アプリとLive接続で別途確認します。

2026-09-20の実API確認では、接続テスト642 ms、曲送り判定539 ms、一時停止203 ms、
否定文202 ms、引用文272 msで応答しました。操作文は期待した操作、否定・引用は操作なしと判定。
いずれもHTTP 200。これは少数の合成文によるAPI単体測定で、実プレイヤーの操作は実行していません。
実際の音声入力から曲が切り替わるまでの時間や、常に同じ精度・速度を保証するものではありません。

公式仕様: [HTTP API](https://docs.typesafe.ai/api)、
[レスポンス型](https://docs.typesafe.ai/sdk/python/api/types/responses)。

## ニケちゃんの表現拡張（試作）

標準AIニケちゃんに限り、画像生成した3ポーズと6種類の身振りをJevで選べます。
設定内の「ニケちゃん・表現拡張（試作）」でON/OFFできます。既定はOFF。
口パク・瞬きは継続し、追加素材の読み込みもON時だけです。
操作、生成プロンプト、素材、再生成、デモの検証条件は
[プロトタイプの設計・手順](nike-flagship-prototype.md)を参照してください。
