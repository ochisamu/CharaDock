# 発話字幕

通常TTSは、生成した音声とその原文を同じ順序で保持する。
初回レスポンスの `audioTexts` は `audioDataUrls` と1対1。
Irodoriの続きは `audioText` と `audioDataUrl` を返す。
文字数から経過秒数を推測して字幕を進めない。

- RLCD: チャンクの字幕シーンをコミットしてから、そのPCMを送信する。
  生成中の回答全文とは別に再生字幕を保持し、後続deltaによる上書きを防ぐ。
- PCマスコット: Audioの再生開始時に同じ文を表示する。
  外部RLCD再生はメインプロセスの字幕通知を使い、再生完了後のIPC応答で全文へ巻き戻さない。
- PCのChat: 発話字幕を優先し、全文・履歴はボタンで展開する。
- 表示は直前＋現在の2チャンク。終了後も残し、既存の「全文」で元の回答を開ける。
  PCは両方を保持。RLCDは4行に収めるため合計88文字を目安に、長い場合は
  直前チャンクの先頭だけを省略する。現在チャンクは削らない。
  新しい会話開始・追加指示・エラー時には前の文をリセットする。
- RLCDの終了字幕は15秒後に破棄し、センサー更新や物音の候補却下による
  シーン再送で古い文を復活させない。PCの全文履歴は残すが、次の発話へ持ち越す
  直前チャンクも終了後15秒で失効する。
- 履歴の全文は書き換えない。音声用の読み替え・URL除去は従来どおり。
- 割り込み後に古い合成が完了しても、その世代の字幕／音声は再生しない。

同期単位は音声チャンク（文・節）であり、単語ごとのハイライトではない。
RLCDではPCM転送・プリバッファ分だけ字幕が音声に先行しうる。
Liveの逐次トランスクリプトは通常TTSとは別経路で、今回の厳密なチャンク対応の対象外。
