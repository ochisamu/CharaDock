# RLCD 4.2: 再生中の曲

Windowsの対応プレイヤーが公開する曲名・アーティストを、Playing（再生中）の間だけRLCDの待機中のHome画面に表示する。曲の再生や曲送りは行わない。

- RLCDを有効にしてUSBまたは認証済みWi-Fiで接続している間だけ、5秒間隔（取得完了から）で読み取り。並行取得しない。
- 複数の再生中プレイヤーがある場合は推測せず非表示。Paused（一時停止）・Stopped（停止）・Closedを含め、再生中がなければ曲情報を消して通常の接続表示へ戻す。Windows側に曲名が残っていても表示しない。
- 停止の反映は次の取得が完了した時点（取得完了から5秒ごと）。再開すると再び曲情報を表示する。PC側の変更だけで対応し、ファームの再書き込みは不要。
- 接続解除・接続先変更・取得失敗・プレイヤー消失では前の値を破棄。遅れて返った旧接続の値は採用しない。
- 表示内容が変わった場合のみ通常のscene同期を予約する。字幕、音声、履歴、メモリ、モデル入力への追加はしない。
- 曲情報はPCから接続先デバイスへのローカル表示用。永続保存やログ記録はしない。既存media_controlツールの明示的な曲名質問は別経路。
- 長い曲名は2行まで。アーティストは1行。会話・作業・承認・エラー中は通常表示を優先。Homeへ戻ると最新の曲情報を使う。

## 互換性

Protocol v2の既存footerテキストを `状態\n曲名\nアーティスト` として送る（全体160 UTF-8 bytes以内）。titleは96 bytes、artistは40 bytes以内。新しいフレーム形式は追加しない。旧ファームウェアは状態の1行だけ表示するため、全項目を見るには更新したRLCDファームウェアが必要。

実装したファームウェアの作業ツリーは Windows側の `C:\Users\ikai\workspace\charadock-esp32\charadock-esp32`。Linux側の同名リポジトリは旧ATOM版なので変更していない。

## 検証

- PC: 自動テスト811件、Python58件、runtime型チェック成功。
- RLCD: PlatformIO通常ビルド成功（upload/flashは実行していない）。
- 実描画コード＋同梱Shinonomeフォントをホスト用framebufferで実行し、日本語2行、アーティスト、pause、クリア後の再描画、会話中の非表示をテスト。
- 端末未接続のため、実機のUSB/Wi-Fi表示・更新タイミングは未検証。profileの再起動も行っていない。
